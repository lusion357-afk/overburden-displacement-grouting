# v0.9 三角底煤修正（把"沿走向 15 m 抬头段"改成"沿倾向 22.5 m 三角底煤"）

> 用户 m00078：「在 v08 的基础上做进 v09，v08 的做三角底煤的思路是错的」。
> 前序：用户 m00001 问错层位开采时"工作面靠近进风巷逐渐抬高、留下未采的煤是什么形状、怎么摆放"，
> 本会话按华丰 4#1411 的文献口径给出结论后，才进入模型改造。

## 一、v08 错在哪

v08 的 `ramp`（抬头段）是**沿走向**的：在箱体 +x 末端 15 m 内把底煤由 0 抬到 4.0 m（14.93°），
并把这一楔形当成"输送机逐节抬溜"留下的煤。问题有三条，都是方向性的：

1. **方向错**：抬溜发生在**工作面端头（倾向）**，不是走向末端。工作面沿走向推进时，
   每一刀都在同一位置（靠近进风巷的一端）抬溜，所以三角底煤沿**倾向**展开、
   沿**走向全长**恒定，不是只在箱体一头冒出来的楔子。
2. **长度错**：22.5 m 是倾向的抬溜水平长（15 节 × 1.5 m 溜槽），不是走向长度。
3. **位置错**：三角底煤在**进风巷（沿煤层顶板）正下方**，从进风巷外帮满厚 4.0 m
   向工作面中部 22.5 m 处尖灭；v08 把它放在箱体 +x 远端，与两条巷道都不搭。

v08 代码注释里写着"若沿倾向渐薄，进风巷下方会出现空腔"——这个担心不成立：
进风巷正下方恰好是三角底煤的**满厚平段**（4.0 m），渐薄发生在平段之外的工作面内。

## 三、改了什么

### `geometry.js`
`ramp` 由走向语义改为倾向语义：

```
rampLenM = 22.5            // 倾向：4.5 平段 + 18 斜边
rampRiseU = coalTop - LANE_H   // 4.0 m
rampSlopeLenM = rampLenM - laneWidthM = 18
rampDeg = 12.5288°
rampZ0 = zLaneIn0          // 进风巷外帮（−z 端）
rampZ1 = zLaneIn0 + rampLenU   // 尖灭点
rampZSlope0 = zLaneIn0 + LANE_W // 平段/斜边交界
```
删除 `rampXStart`；`__GEO__` 同步输出上述键。

### `scene.js`
- C 段（常规开采段，96 段）每段沿倾向切 4 块：
  1. 进风巷带 `0→LANE_TOP_Y0`、`z∈[Z_IN0,Z_IN1]`，`'ramp'`（永久）；
  2. 斜边 18 块 `0→thick`，`thick = rampRiseU·(1−(j+0.5)/18)`，`'ramp'`（永久）；
  3. 平段/尖灭点之外 `0→M_U`，`'mining'`（采动后消失）；
  4. 回风巷带 `LANE_H→M_U`，`'mining'`。
  → 三角底煤 **96 段 × 19 块 = 1824 块**，沿走向全长恒定。
- 删除 v08 的 D 段（走向 15 m 抬头楔，30 块）与 `laneInRamp/laneRetRamp`；
  进风/回风巷空腔各 96 段沿走向全长贯通（v08 的"下侧巷道没掘通"随之消失）。
- 标签改为「三角底煤 · 倾向 22.5 m · 0→4.0 m」，锚点在进风端三角煤上。
- lanes 机位与剖切面**回到 v0.8 口径**（+z 侧、`zLaneRet0−0.10`）。

### `lane-section.js`（倾向剖面，本版主角）

## 五、可见性说明（重要）

三角底煤全厚 4.0 m = 0.18 场景单位，在 1440×1000 全景里约 6 px，且位于箱体 **−z 岩层端墙之下**：
Three.js 裁剪只能剪掉远侧露出切口，而三角煤本身就是最靠近该端头的几何——从任何外部机位
要么被岩层端墙挡住，要么连三角煤一起剪掉。**因此 3D 只保证几何正确（1824 块 + G8 断言），
可见性由 `#lane-inset` 倾向剖面承担**（等比 17.7 px/m，4.0 m ≈ 71 px）。
这符合工作区纪律 §二"先算可见性，再做几何"：不可辨的不做视觉放大，改由 2D 交付。
