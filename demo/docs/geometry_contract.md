## 1 一句话

模型里任何一个三维坐标，只允许由 `geometry.js` 的少数几个函数算出来；
`data/geology.js` 是唯一的数字来源，`geometry.js` 是唯一的换算入口，
`scene.js` / `overburden-three-zones.js` 只允许**读取**，不允许自己写换算式。

## 2 数据流（单向，不可回环）

```
data/geology.js          ← 唯一数值来源（每条带 tag + src）
      │  window.MINE_DATA
      ▼
geometry.js              ← 唯一换算入口（SLOPE / coalTop / yBase / frame / yFromData …）
      │  window.__GEO__
      ├──▶ scene.js                     地层、煤、巷道、设备、相机、箱体
      ├──▶ overburden-three-zones.js    覆岩三带
      ├──▶ mining-volume.js             采空区（S1 起启用）
      └──▶ grout-volume.js              离层浆体（S3/S4 起启用）
      │
      ▼
_refs/verify_geometry.js ← 同一套函数做断言（禁止在断言里重算一遍再自证）
```

**禁止的反向依赖**（v0.5 的原病）：
- 由 `SURF_Y` 反推 `coalTop`（v0.5 `SEAM_TOP = 7.05 − 150/S` 即此类，已废）
- 由箱体尺寸反推采高
- 在 scene.js 里裸写 `SLOPE*z`（v0.5 分散约 10 处，无法审计）

## 4 倾角变换：唯一入口

### 4.1 为什么是剪切而不是旋转

旋转会把矩形截面煤层转成菱形，破坏岩层之间的拼接面；剪切保持 x 向不变、
只让 y 随 z 线性抬升，岩层仍保持"原样叠置、整体倾斜"的外观。
**这是电子表达的选择，不是力学计算**——标 `设定`。

### 4.2 唯一公式

```js
SLOPE = tan(30°) = 0.5773502691896257
yBase(z) = (z + zHalf) · SLOPE           // zHalf = 3.20253
帧坐标   = { x, y: yBase(z) + yLocal, z }
```

`yBase(-zHalf) = 0`；`yBase(0) = 1.84898`；`yBase(+zHalf) = 3.69796`（= 81.984 m 的两端高差）。

### 4.3 实现方式：一个矩阵，而不是一百处加法

`scene.js:87-95` 建一个 `strata` 组，`matrixAutoUpdate=false`，只设一次矩阵：

```
y_W = y_L + SLOPE·z + yBase(0)
```

即 `y_W = yBase(z) + y_L`。所有地层、煤、采空区、三带、浆体**作为 strata 的子物体
用局部坐标建模**（`y_L = (yD + M) / S`，z ∈ ±zHalf），剪切由这一处矩阵统一施加。

**这样做的理由**：指令 §4.3 要求"唯一入口、禁止裸写"；用一个父组矩阵，
比在每个几何体上调用 `frame()` 更彻底——子孙物体根本拿不到世界坐标，
想写错也写不出来。

### 4.4 局部坐标系的定义（务必记住）

| 局部 y | 含义 |
|---|---|
| `-0.55 / S − coalTop` | 底板底 |
| `0` | **煤底** |
| `coalTop = 0.27966` | 煤顶 |
| `U(150) = 7.04556` | 地表 |
| `U(88) = 4.24899` | 主关键层底（注浆层位） |

`U(m) = m / S + coalTop`（米 → 局部单位）。`M_U` 就是 `coalTop`。

**注意**：局部坐标的 0 是煤底，不是地表。v0.5 把 0 当地表，这是"双坐标系"病根之一，
已由 G1a/G1b/G1c 三条断言锁死（往返回差 = 0）。

### 5.1 三条判据的落点（S1 实现，2026-10-25）

| 判据 | 内容 | 代码落点 | 断言 |
|---|---|---|---|
| ① 进风巷沿煤层顶板 | `y_top = coalTop` | `scene.js` `cavity(X_CUT1,S1X1,LANE_TOP_Y0,M_U,Z_IN0,Z_IN1,twins)` | G5 |
| ② 回风巷沿煤层底板 | `y_bot = 0` | `scene.js` `cavity(X_CUT1,S1XR,0,LH,Z_RT0,Z_RT1,twins)` | G6 |
| ③ 分居两端头、相距一个面长 | `z ∈ ±(zHalf − w)` | 上式 z 区间 | G4a/G4b/G4c |

**巷道是负空间**：煤体在巷道位置不生成（`coalBox()` 留缺口），缺口内壁用 BackSide 盒
表达。禁止用 `BoxGeometry` 实体盒冒充巷道（m00851 指出的错误）。
v0.6.0-S1f：用户要求不显示绿色轮廓线 → `scene.js` 的 `SHOW_LANE_EDGES=false`，不再生成
`EdgesGeometry` 轮廓；煤体缺口与 BackSide 内壁不变，G3~G9 断言不依赖轮廓线。
煤层分三类：工作面内部（`mining`，随推进采空）、两端头巷道煤带（`pillar`，沿空留巷
永久保留）、三角底煤（`ramp`，永久）。注意 v0.8 起两端头煤带已按"一次采全高"改回 `mining`
（`pillar` 类在 v0.8 无实例）；v0.9 起 `ramp` = 倾向三角底煤（进风巷下方满厚 4.0 m 平段 +
18 m 斜边尖灭，沿走向全长 96 段 × 19 块 = 1824 块）。

走向范围：切眼 `xFace = −5.0`，箱体 `x ∈ ±5.999098`；未采动区 `[−5.999, −5.0]` = 22.15 m
（`G.notMinedLenU`，X6 锁死）。切眼宽 4.5 m、沿倾向贯通全幅。

三角底煤（**v0.9 修正**：v0.6-S1h~v0.8 曾误放在走向末端 15 m）：位于**进风巷（沿煤层顶板，
`−z` 端头）正下方**，沿**倾向**水平长 22.5 m（`z ∈ [zLaneIn0, zLaneIn0 + rampLenU]`），
其中 `z ∈ [zLaneIn0, zLaneIn0 + LANE_W]`（4.5 m，进风巷正下方）为满厚 4.0 m 平段，
其余 18 m 斜边线性收薄到 0，坡度 `atan(4.0/18) = 12.5288°`（G8 系列锁死）；
**沿走向全长恒定**（不是只在箱体一头）。抬升量不是自由参数：
起点巷道贴煤底、终点巷道顶贴煤顶，故累计抬升只能是 `煤厚 6.2 − 巷高 2.2 = 4.0 m`。
依据：赵景礼 2004（溜槽逐节抬升 3°/4°、累计 12°~15°、曲边三角形煤损）、
王志强 2024/2026 式(1)(2)（`h = 1.5636 + 0.388229n`，15 节 × 1.5 m = 22.5 m）。

### 5.2 为什么 3D 全景里看不见双巷（必须交代，不是 bug）

- 断面 `0.203 × 0.0992` 单位（真实 4.5 m × 2.2 m，**不放大**）。在 1440×1000 视口、
  12 单位宽的箱体里约 **3.7 × 1.8 px**，低于工作区纪律 §二的 2 px 可见性阈值。
- 进风巷位于 z=−3.2 端头的实心煤体内（被 +z 侧煤体遮挡）；回风巷位于 z=+3.2 端头、
  贴底且上方还有 4.0 m 煤，从任何外部视角都看不到腔体。
- 本版**不做布尔剖切**（`clippingPlanes`），也**不放大巷宽**：剖切会同时切开岩层与
  设备、改变整页外观，与"完整实验箱"的表达冲突；放大巷宽会让 4.0 m 层位差与 142 m
  面长失去同一把尺。
- 因此可见性由 §6.2 的 2D 剖面承担；3D 中保留真实位置几何与文字标签，标签指向的是
  **位置示意**，不是可辨轮廓。

### 6.1 台架垫块的来历（必须交代）

30° 剪切后，岩层底面在箱体内是**斜平面**（世界 y 从 −0.945 抬到 +2.984），
而实验箱底是水平的，两者之间必然留一个三角空腔。
真实相似模拟里的对应物是**可调倾角台架的楔形垫块**——这不是凭空补的几何，
是那台装置的物理构件。
实现：`scene.js:270-284`，一块手写 8 顶点棱柱，挂在 `lab` 组（**不进 strata**，因为它必须与水平箱底贴合）。
**它不代表任何岩层，也不参与任何断言**；报告与答辩中若要提到它，必须说"台架垫块"。

### 6.2 倾向剖面放大镜（S1 的可见性交付物）

文件：`lane-section.js` + `index.html` 的 `figure#lane-inset` + `styles.css` 的 `.lane-inset` 段。
位置：3D 视口**下方独立条带**，不做浮层叠加——浮层会遮挡"未注浆"对照组。

四条纪律：

1. **等比**。横纵同一比例尺，`SCALE = min(可用高 / M_M, 可用宽 / (左段 + 右段))`，
   `anisotropy = 1`。倾角与断面形状都不被拉伸。
2. **真实尺寸**。巷宽 `G.LANE_W = 4.5 m`、巷高 2.2 m、煤厚 6.2 m，与 3D 同一把尺（3D 已无放大）。

   **比例尺不被破坏**，只是省略中段。v0.9 把画布扩到 720×210（等比 17.7 px/m）：
   三角底煤回到**倾向**剖面（进风端 22.5 × 4.0 m），本图正是它的可见性交付物。

`window.__LANE_SECTION__` 输出 `drawn / scalePxPerM / anisotropy / coalThicknessM /

## 7 两处指令内部矛盾（已登记，未静默处理）

### 矛盾 ①：G11 注浆层位的期望值

- 指令 §5 断言表写 `4.2454`。
- 按契约自身的 `S = 22.17`、`M = 6.2`、注浆层位 88 m 计算：
  `(88 + 6.2) / 22.17 = 4.24898512`。
- 两者差 `0.003585 u = 0.0795 m`。反解：若 `4.2454` 正确，则 `S ≈ 22.19` 或 `M ≈ 6.12`。

**处置**：断言按公式取值（4.24898512），并在 `verify_geometry.js` 输出显式示警；
不采用指令里的字面数字，也不删掉这行示警。**待用户裁决**。

### 矛盾 ②：`frame()` 的形式

- 指令 §4.3：`frame(y,z) = y + SLOPE·z`
- 指令 §4.4：`yBase(z) = (z + 5.64)·SLOPE`，且巷位/起坡的断言式都按 `yBase(0)` 写。

两式相差常数 `zHalf·SLOPE = 1.84898`。若按 §4.3 字面执行，§4.4 全部断言会整体偏移 1.85 单位（41 m）。

**处置**：统一采用 `yW = yBase(z) + y_L`（即 §4.4 形式），因为断言的判据是 §4.4。
`geometry.js:frame()` 内部用 `yBase(z)`；G7（倾角反算 30.000°）与 G5/G6（巷位）
在两种写法下结果相同（常数偏移不影响斜率与相对差），所以此裁决不改变任何门禁结论。

## 8 `?v=` 取代 `_r21` 的决定（与工作区纪律的偏离，需声明）

工作区 `AGENTS.md` §三要求：任何脚本改动必须同时改基础名与 `_r21` 副本。
**v0.6 不采用 `_r21` 机制**，改用 URL 查询参数强制刷新：

```html
<script src="scene.js?v=06s1b"></script>
```

理由：
1. v0.6 是**新工作副本**（新目录），不存在"旧缓存命中"的历史包袱；
2. `_r21` 的代价是每改一处要维护两份文件，哈希比对成为新的出错来源；
3. `?v=` 每次发版只需改一个字符串，且不产生重复文件。

**代价与约束**：每次改动脚本内容，必须同步递增 `?v=`（当前 `06s1b`）。
若忘记递增，浏览器会拿旧缓存——这类错误在无头探针里表现为"改了没效果"。
本文件与 `CHANGELOG.md` 各记一条。

### 9.4 `lanes` 剖切机位（v0.6-S1c）

巷道是煤层中的负空间，从任何外部机位都被煤体或覆岩挡住。`lanes` 机位改用**几何剖切**而非透视：

- `renderer.localClippingEnabled = true`（`scene.js:58`）；
- 剖切面 `clipLane = new T.Plane(new T.Vector3(0,0,1), -(G.zLaneRet0-0.10))`（`scene.js`），保留 `z > zLaneRet0−0.10 = 2.89955` 的薄片——恰在回风巷（`z ∈ [2.9995, 3.2025]`）外侧，切掉中间带煤的遮挡；
- `setLaneClip(on)`（`scene.js`）遍历 `world` 与 `counterScene` 同步材质 `clippingPlanes`，并把 `mats.coal.side` 切到 `DoubleSide`，使切口露出煤体而非空洞；
- 切入 `chooseCamera()`：`setLaneClip(name==='lanes')`（`scene.js`）；切面沿倾向（yz 面）展开，因此**呈现贴底的回风巷与煤层断面**；
- `lanes` 的 fov 取 30（`scene.js`），局部放大煤层厚度。

这一机位**只显示 +z 端头**（回风巷）；进风巷（−z 端头）、三角底煤与两巷的整体层位关系仍由 `#lane-inset` 倾向剖面承担。
**v0.9 起三角底煤在倾向剖面里，但 3D 中它位于箱体 −z 岩层端墙之下，从任何外部机位都剖不到**
（裁剪只能剪掉远侧露出切口，而三角煤本身就是最靠近端头的几何）——3D 只保证几何正确，可见性由 2D 剖面交付。
