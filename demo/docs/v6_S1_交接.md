### 3.1 三处已确认的实现错误（用户 m00851 / m00882 指出，代码尚未修正）

1. **实体 vs 负空间**：`laneSlot()` 用 `BoxGeometry` 在煤层里放实体黑盒。巷道应是煤层中被**掏空**的通道，盒子只能用于掏空面的着色，不能是实体块。
2. **两巷位置**：现实现两巷都居中 `z=0`、仅高度差 4.0 m。真实是分居工作面**倾向两端头**，相距一个面长（142 m）。
3. **4.0 m 的含义**：`6.2 − 2.2 = 4.0` 是**同一端头**"贴顶巷道底"与"贴底巷道顶"的层位差，**不是**两巷位置差。

## 4 S1 几何定义（已定案，m00942 + m00957）

```
x 轴 = 走向（切眼在负端，推进朝 +x）；z 轴 = 倾向；y 轴 = 垂直（Z-up）
箱体          x ∈ [−5.999, +5.999]（12 单位 = 266 m）
切眼          xFace = −5.0
未采动区      x ∈ [−5.999, −5.0]（0.999 单位 ≈ 22.15 m）：完整实体煤层，全厚 6.2 m
采空区        x ∈ (−5.0, +5.999]：煤层已采出（综放一次采全高），顶板垮落
```

| 构件 | 位置 | 尺寸（真实值，不乘视觉系数） |
|---|---|---|
| **进风巷**（贴顶板） | `z = −zHalf` 端头，沿 `x` 贯通 `[−5.0, +5.999]` | 4.5 m 宽 × 2.2 m 高，顶板与 `coalTop` 齐平 |
| **回风巷**（贴底板） | `z = +zHalf` 端头，沿 `x` 贯通 `[−5.0, xRampStart]` | 4.5 m 宽 × 2.2 m 高，底板与煤层底板（local 0）齐平 |
| **起坡段** | `z ∈ [+zHalf − 4.5m, +zHalf]`、`x ∈ [xRampStart, +5.999]` | 15 节 × 1.5 m = **22.5 m**，残留煤厚由 0 阶梯增至 6.2 m → 坡度 **15.4°** |
| **切眼** | `x = −5.0`，连接两端头，沿 `z` 贯通全幅 | 宽 4.5 m，高 6.2 m（贯通全煤厚） |

- **巷道是负空间**：用煤层几何在 `coalBand()` 里留缺口表达，缺口内壁着色 + 轮廓线；**不得**用 `BoxGeometry` 实体块填充。
- **两端头绝对高差**由倾角自然产生：单面方案下 `rise − coalTop = 3.4183 单位 = **75.78 m**`。`6.2 − 2.2 = 4.0 m` 只是**同一端头**的层位差，两者不可混用。
- **起坡段的物理含义**：论文 :847-849 端部逐节抬溜 3°~4° 累计 12°~15°，:855-856 预铺金属网/再生顶板成为下区段回风巷的人工顶板。本案 22.5 m 抬高 6.2 m → 15.4°，落在论文区间内；它**不是巷道的一段斜段**，而是**回风端头采空区内残留的楔形煤体**。
- **倾向剖面放大镜**（`lane-section.js`）改为**垂直煤层的等比例剖面**：把 30° 倾角展开为水平带，进风巷贴上边缘、回风巷贴下边缘，标「倾向 142 m」「巷宽 4.5 m」「巷高 2.2 m」，图注写明本图**不表达倾角**。

## 7 已知陷阱（交接待续时必须知道）

1. **PowerShell 无 `[System.Web.HttpUtility]`** → 用 `[System.Net.WebUtility]::HtmlDecode`。
2. **`canvases[0]` 恒为 `null`**（主 WebGL canvas 无 `preserveDrawingBuffer`），不能据此判断主场景是否渲染 → 必须截图目视。
3. **两次截图字节数相同 ≠ 改动无效**：页面初始恒在进度 0，本来就是同一帧。判据只能用 DOM/几何探针或局部裁剪。
4. **`--virtual-time-budget=9000` 时页面仍 `loading`**，verify 脚本未执行，会误判为"脚本没加载"。用 25000，探针用轮询 `collect()`。
5. **node 追加脚本**：第一个用户参数是 `argv[2]`，`argv[1]` 是脚本自身路径（曾把 CSS 追加进脚本自己）。
6. **`read` 工具读 UTF-8**；PowerShell `Get-Content` 会按 GBK 解码出乱码。
7. **截图 < 100 KB** = 页面白屏/语法错误。
